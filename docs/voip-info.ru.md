# voip-info

Терминальный интерфейс в духе k9s для наблюдения за open-source VoIP/RTC-экосистемой: релизы и ветки
66 продуктов (Asterisk, FreeSWITCH, Kamailio, OpenSIPS, rtpengine, WebRTC-серверы, SIP-стеки, Voice AI,
тестовые инструменты), активность проектов на GitHub, уязвимости с оценкой реального риска, ваши версии
в продакшене, новости, рынок, стандарты IETF и конференции. Дайджест за период - на экране или в Markdown.

English version: [voip-info.md](voip-info.md).

## Установка

Готовые бинарники для Linux и macOS - на странице [Releases](https://github.com/napadailo/voip-info/releases).
Или через Go 1.22+:

```sh
go install github.com/napadailo/voip-info/cmd/voip-info@latest
```

Из исходников:

```sh
make build      # bin/voip-info
make install    # в $GOPATH/bin
make test
```

Программа - один файл: каталог продуктов, лент и вендоров встроен в бинарник, база - SQLite на чистом Go,
CGO не нужен.

## Первый запуск

```sh
voip-info                    # интерфейс, стартовый вид - продукты
voip-info -lang ru           # язык интерфейса
voip-info -c releases        # стартовый вид или карточка: -c asterisk
voip-info -theme nord        # тема
voip-info -sample-config     # пример конфига
voip-info -version
```

При запуске программа в фоне загружает:

- релизы всех продуктов из `releases.atom` GitHub (без лимитов);
- метрики GitHub API: звёзды, коммиты, issue, PR, milestones, security advisories (с токеном);
- уязвимости из NVD, каталог CISA KEV и оценки EPSS;
- новости, котировки вендоров, черновики и RFC IETF, встречи IETF, новости конференций;
- статистику пакетов npm, PyPI и Docker Hub.

Всё кэшируется в базе; повторные запросы к GitHub идут с ETag и лимит не тратят. Без ключа NVD первая
загрузка уязвимостей занимает около 3 минут (NVD разрешает 5 запросов в 30 секунд), с ключом - около
20 секунд; прогресс виден в шапке (`NVD 12/28`). `r` перезагружает всё из сети.

### Шапка

| Строка | Что показывает |
|---|---|
| Токены | есть ли токен GitHub (без него 60 запросов в час) и ключ NVD |
| API | остаток лимита GitHub API и время сброса |
| Категория | текущая категория и число её продуктов |
| Новых релизов | непросмотренные релизы и новости за 24 часа |
| CVE/30д | новые уязвимости за 30 дней, из них high/critical, уязвимости каталога в CISA KEV; прогресс NVD |
| Обновлено | время последней загрузки и язык интерфейса |

## Конфигурация

Конфиг - `~/.config/voip-info/config.yaml` (`$XDG_CONFIG_HOME/voip-info/config.yaml`, путь меняет
`$VOIP_INFO_CONFIG` или флаг `-config`). Файла может не быть: всё работает и без него, но без токенов.

```yaml
theme: nord                # :theme показывает все, свои - в themes
language: ru               # en, ru; по умолчанию из LANG; :lang переключает
dataDir: ~/.local/share/voip-info   # кэш и состояние
digest:
  days: 7                  # период :digest и voip-info digest по умолчанию
  mine: true               # по умолчанию только «мой стек»
secrets:                   # где лежат токены; секрет без настроек не читается
  github:   {command: gh auth token}
  nvd:      {command: security find-generic-password -s voipinfo-nvd -w}
themes:
  noc: {base: nord, accent: "#ffaf00"}
```

Тема и язык, выбранные через `:theme` и `:lang`, запоминаются. Приоритет: флаг, конфиг, последний выбор,
значение по умолчанию.

### Секреты

Токены никогда не хранятся в конфиге и в коде - конфиг только говорит, где их взять. У каждого секрета три
источника, проверяются по порядку, срабатывает первый непустой:

| Источник | Что это | Где удобно |
|---|---|---|
| `env` | переменная окружения | разовый запуск, CI |
| `file` | файл с секретом (`~/` - домашний каталог) | Linux-сервер (файл `0600`), Docker и Kubernetes secrets (`/run/secrets/…`), systemd `LoadCredential` |
| `command` | команда, которая печатает секрет (через `sh -c`) | любой менеджер секретов: `pass show …`, `op read …`, `secret-tool lookup …`, `vault kv get …`; на macOS - связка ключей |

Без настроек секрета нет: никаких имён переменных по умолчанию, никакого неявного `gh auth token`.

| Секрет | Зачем |
|---|---|
| `github` | метрики GitHub API: 5000 запросов в час вместо 60. Достаточно fine-grained токена с доступом «Public repositories (read-only)»; токен `gh` - `command: gh auth token` |
| `nvd` | ключ NVD API: загрузка уязвимостей в 10 раз быстрее. Бесплатно: https://nvd.nist.gov/developers/request-an-api-key |

Связка ключей macOS:

```sh
security add-generic-password -U -a "$USER" -s voipinfo-github -w     # спросит токен; -U заменяет
```

```yaml
secrets:
  github: {command: security find-generic-password -s voipinfo-github -w}
```

Пока Mac разблокирован, связка открыта, и задания cron тоже видят секреты.

`voip-info secrets` показывает, где нашёлся каждый секрет и почему не нашёлся, не печатая значений:

```
github    found by the command
nvd       found in the file /etc/voip-info/nvd.key
```

### Данные

Каталог данных - `~/.local/share/voip-info` (`$XDG_DATA_HOME/voip-info`, `dataDir` в конфиге или
`$VOIP_INFO_DATA`):

| Файл | Что в нём |
|---|---|
| `voip-info.db` | кэш HTTP-ответов, просмотренные релизы, ежедневные снимки метрик (звёзды, индекс здоровья, pulls), выбранные тема и язык |
| `inventory.yaml` | мои версии (`:have`), редактируется и руками |
| `watch.yaml` | подписка «мой стек» (`w`, `:watch`) |
| `exports/` | сохранённые дайджесты (`:export`, `e` в окне дайджеста) |

При первом запуске мои версии и подписка импортируются из `~/.voipinfo` (или `$VOIPINFO_HOME`) - данных
прежней Python-версии.

## Клавиши

| Клавиша | Действие |
|---|---|
| `j` `k` `g` `G` `ctrl-d` `ctrl-u` | перемещение |
| `enter` | открыть: карточку продукта, уязвимость, новость, релиз |
| `esc` / `q` | назад (`esc` сначала сбрасывает фильтр) |
| `/` | фильтр строк (regex, `!` инвертирует); поиск в текстовых окнах, затем `n` / `N` |
| `:` | командная строка с дополнением и историей |
| `o` / `O` | колонка сортировки / направление; пустые ячейки всегда в конце |
| `h` / `l` | прокрутка широких таблиц |
| `b` | открыть в браузере страницу строки: релиз, уязвимость, новость, репозиторий |
| `0`-`9` | категория (`0` - все); в `:news` - тип ленты |
| `w` | подписаться на продукт, тему, вендора или рабочую группу строки (повторно - отписаться) |
| `W` | во всех видах только «мой стек» |
| `r` | перезагрузить всё из сети |
| `n` | отметить все релизы просмотренными |
| `R` | в `:security` - сортировка по реальному риску |
| `?` | справка: клавиши и команды |
| `:theme`, `:lang` | тема с предпросмотром, язык интерфейса |
| `:q` | выход |

Каждый вид показывает свои клавиши в шапке. Категории: `1` PBX, `2` SIP Proxy, `3` Media/RTP, `4` WebRTC,
`5` SIP Stack, `6` Monitoring, `7` CPaaS/AI, `8` Codec/DSP, `9` Testing, `0` все. Их же можно набрать
командой: `:pbx`, `:sip`, `:media`, `:webrtc`, `:stack`, `:mon`, `:ai`, `:codec`, `:test`, `:all`.
`:<id>` открывает карточку продукта, например `:asterisk`.

## Виды

### `:products` - продукты

По строке на продукт, сверху - самые свежие релизы.

| Колонка | Что это |
|---|---|
| ИМЯ | `◆` - есть в «моих версиях», `◉` - в подписке или зависимость подписанного; зелёное - есть непросмотренные релизы; `…` - загружается, `!` - фид не загрузился |
| КАТЕГОРИЯ | категория каталога |
| ЛАТЕСТ | последний стабильный релиз; у проектов без релизов - последний коммит `⎇ sha` |
| ИЗМЕНЕНИЯ | метки release notes этого релиза: `SEC` `BRK` `DEP` `FEAT` `FIX`, у каждой свой цвет; `-` - заметок нет |
| PRE | пре-релиз (rc, beta), если он новее стабильного |
| ВОЗРАСТ | сколько прошло с последнего стабильного релиза: до 30 дней зелёный, до года обычный и жёлтый, дальше красный |
| NEW | непросмотренные релизы (первый запуск считает новыми релизы за 14 дней; `n` отмечает всё) |
| CADENCE,D | медианный интервал между стабильными релизами в днях |
| STARS | звёзды и прирост за неделю (`17k +18`), прирост - по ежедневным снимкам |
| COMMITS | коммиты за 8 недель спарклайном и тренд: 12 недель против 12 предыдущих (не показывается, если раньше было меньше 10 коммитов) |
| CVE 1Г | собственные уязвимости за год, цвет - по самой серьёзной; `0` - источник есть, уязвимостей нет; пусто - источника нет |
| CVE ЗАВИСИМ. | high/critical уязвимости зависимостей за 180 дней без исправления: `ok`, `3 ✗` - ждёт релиза продукта, `2 ↻` - обновить зависимость отдельно |
| ЗДОРОВЬЕ | индекс здоровья 0-100 |
| STATUS | по последнему стабильному релизу: hot до 30 дней, active до 4 месяцев, slow до года, stale дольше |

### `:releases` - лента релизов

Все релизы всех продуктов (примерно последние 10 каждого), новые сверху: дата, возраст, продукт, тег,
ветка, stable/pre, метки изменений и риск обновления. `●` - непросмотренные. `enter` открывает карточку
продукта на этом релизе. Фильтр `/SEC` - только релизы с исправлениями безопасности.

### `:health` - индекс здоровья

Индекс и шесть компонентов каждого продукта полосками, изменение за неделю, доля веса, посчитанная по
данным. Как считается - в разделе [Индекс здоровья](#индекс-здоровья).

### `:eol` - поддержка веток

Для каждой ветки: тип (LTS / standard), последний релиз, дата x.0, конец полной поддержки, EOL, дней до
EOL, статус и ближайшее изменение. См. [Поддержка веток](#поддержка-веток).

### `:deps` - граф зависимостей

Связи «продукт → зависимость» с типом, последним релизом зависимости и радиусом поражения: сколько
продуктов унаследуют уязвимость зависимости по сильным связям. См. [Граф зависимостей](#граф-зависимостей).

### `:security` - уязвимости

Уязвимости всех продуктов из NVD и GitHub Security Advisories, объединённые по CVE: дата, severity, CVSS,
EPSS, KEV, продукт, сколько продуктов её наследуют, ID, суть, источник. Сверху новые; `R` сортирует по
реальному риску: сначала эксплуатируемые (KEV), затем вероятность эксплуатации (EPSS), затем CVSS.
`enter` - карточка уязвимости: угроза, уязвимые диапазоны версий и где исправлено, кто наследует, задевает
ли вашу версию, описание.

### `:kev` - эксплуатируемые уязвимости

VoIP/UC-записи каталога [CISA KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog)
(Asterisk, FreePBX, Mitel, Avaya, 3CX, Cisco UC, SBC…), в том числе вендоров вне каталога: дата добавления,
CVE, вендор, продукт, ransomware, EPSS и наш продукт, к которому относится CVE.

### `:mine`, `:have`, `:upgrade` - мои версии

`:have asterisk 20.18.0 lab` записывает версию, `:have asterisk -` удаляет. Список хранится в
`inventory.yaml` каталога данных.

| Колонка | Что это |
|---|---|
| ВЕТКА, ПОДДЕРЖКА | ветка вашей версии и её статус из `:eol` |
| ПОСЛЕДНИЙ В ВЕТКЕ, ОТСТАВАНИЕ | куда обновляться без смены ветки и сколько релизов вышло после вашей |
| CVE, HIGH+, KEV | уязвимости, задевающие именно вашу версию (по диапазонам версий GitHub advisories и CPE в NVD) |
| ОБНОВЛЕНИЕ ЗАКРОЕТ | сколько из них закроет обновление до последнего в ветке |
| БЕЗ ДАННЫХ 1Г | уязвимости за год без диапазонов версий или в модулях FreePBX - стоит проверить вручную |
| CVE ЗАВИСИМ. | уязвимости зависимостей за год без исправления |
| ДЕЙСТВИЕ | рекомендация |

Рекомендация (первое подходящее правило): уязвимость из KEV - «СРОЧНО», high/critical - «обновить»,
ветка без поддержки - «планируйте миграцию», есть релизы новее - «доступно обновление», ветка в режиме
только безопасности - предупреждение, иначе «актуально». Цвет: красный, жёлтый, синий, зелёный.

`enter` - сводка по версии и список уязвимостей с объяснением каждой («исправлено в 3.6.9», «нет данных
о версиях», «PJSIP ✗ ждёт релиза»); `enter` по уязвимости открывает её. `u` - путь обновления, `c` -
карточка продукта на вкладке Security.

`:upgrade <id> [с] [до]` (или `u` в `:mine`) - путь обновления внутри ветки: все релизы между версиями
(история дочитывается через `tags.atom`, если фида не хватает), риск, сколько релизов с исправлениями
безопасности и с breaking changes, какие CVE закроются и какие останутся, все UpgradeNote и breaking
changes по релизам. У финальных релизов Asterisk полный changelog подтягивается по ссылке «Full ChangeLog».

### `:news` - новости

24 ленты: блоги проектов, отраслевые издания, Google News (рынок, voice AI, безопасность), Hacker News,
рассылки Kamailio и OpenSIPS (письма сгруппированы в треды), форум Asterisk, русскоязычные источники и
Казахстан. Новости привязываются к продуктам каталога по названию. `1`-`6` выбирают тип ленты: project,
industry, market, regional, community, lists; `0` - все. `enter` - новость целиком.

### `:radar` - радар тем

19 тем (Voice AI, STIR/SHAKEN, мошенничество, Media over QUIC, WebRTC, шифрование, постквантовая
криптография, кодеки, IMS/5G, RCS, Teams, Kubernetes, отказ от меди, регулирование, контакт-центры,
экстренные вызовы, STT/TTS, уязвимости, сделки): упоминания за 7 и 30 дней, тренд (последняя неделя
против средней недели месяца), спарклайн за 12 недель, источники (новости, release notes, IETF, рассылки),
с какими продуктами тема встречается. Темы ищутся по ключевым словам на английском и русском. `enter` -
сводка темы и список упоминаний, `b` открывает упоминание.

### `:ietf` - стандарты

Черновики (за год) и RFC (за два года, с датой публикации) рабочих групп sipcore, stir, mmusic, avtcore,
moq, wish, ecrit, webtrans из datatracker: дата, тип, группа, документ с ревизией, название, страницы, срок
истечения черновика. `enter` - аннотация, `b` - документ на datatracker.

### `:events` - события

Встречи IETF с точными датами и конференции (FOSDEM, Enterprise Connect, Kamailio World, OpenSIPS Summit,
ClueCon, AstriCon, RTC.ON) с обычным месяцем проведения и последним упоминанием в новостях. `enter` по
конференции - сводка и список упоминаний.

### `:market` - рынок

15 вендоров (Sangoma, Twilio, RingCentral, 8x8, Bandwidth, Ooma, Five9, Zoom, Vonage, 3CX, Avaya, Mitel,

## Мой стек

«Мой стек» - то, что относится к вам: продукты из «моих версий», подписка (`w` на строке любого вида или
`:watch <id|тема|вендор|wg>`) и все зависимости этих продуктов. Подписаться можно на продукт, тему радара,
вендора и рабочую группу IETF; `:watch voice` найдёт тему по части названия.

`W` оставляет во всех видах только стек: в списках продуктов - его продукты, в `:news` - новости о них и о
подписанных темах, в `:radar`, `:market`, `:ietf` - подписанные темы, вендоры, группы. Режим запоминается.
В дайджесте стеку посвящён первый раздел, `:digest mine` - только он.

## Дайджест

`:digest [дни] [mine|all]` - полный дайджест за период одной страницей: мой стек, мои версии, KEV,
уязвимости (по риску), уязвимости, протекающие через зависимости, значимые релизы (новые мажорные версии и
ветки), пре-релизы, патч-релизы, сроки поддержки веток, сигналы по проектам (ускорение и замедление
коммитов, лидеры и аутсайдеры индекса здоровья, использование, архивированные), рынок, стандарты, радар,
ближайшие встречи IETF, новости по типам без дублей. В окне дайджеста `e` сохраняет его в `.md`.

`:export [дни] [mine]` - сохранить полный дайджест в `exports/` каталога данных.

## Без интерфейса

```sh
voip-info digest [-days N] [-mine | -all] [-out FILE]
voip-info secrets
```

`voip-info digest` загружает все данные и печатает полный дайджест в stdout, `-out` пишет его в файл.
`-days` по умолчанию из `digest.days` конфига, иначе 7; `-mine` - только «мой стек», `-all` - полный, даже
если в конфиге `digest.mine: true`.

cron, по понедельникам в 9:00 (`crontab -e`, путь - из `which voip-info`):

```
0 9 * * 1 /Users/имя/go/bin/voip-info digest -days 7 -mine -out /Users/имя/digest.md
```

Если секреты в связке ключей macOS, Mac в это время должен быть включён и разблокирован. На Linux удобнее
systemd timer и секреты в файлах:

```ini
# ~/.config/systemd/user/voip-info-digest.service
[Service]
Type=oneshot
ExecStart=%h/go/bin/voip-info digest -days 7 -mine -out %h/digest.md

# ~/.config/systemd/user/voip-info-digest.timer
[Timer]
OnCalendar=Mon 09:00
Persistent=true
[Install]
WantedBy=timers.target
```

```sh
systemctl --user enable --now voip-info-digest.timer
```

## Как считается

### Индекс здоровья

0-100, шесть компонентов:

| Компонент | Вес | Шкала |
|---|---|---|
| Свежесть релизов | 25 | дней с последнего стабильного: ≤30 - 100, ≤90 - 85, ≤180 - 60, ≤365 - 30, дольше - 5 |
| Регулярность | 10 | медианный интервал: ≤30 - 100, ≤60 - 85, ≤120 - 60, ≤240 - 35, дольше - 10 (нужно 3 релиза) |
| Темп разработки | 20 | коммиты за 12 недель по логарифму: 120+ - 100, 10 - около 50; падение больше чем вдвое - ×0.75 |
| Отзывчивость | 15 | issue за 30 дней: половина - доля закрытых, половина - медиана закрытия (≤7 дней - 100, ≤30 - 70, ≤90 - 40) |
| Сообщество | 10 | авторов смёрженных PR за 30 дней: 1 - 15, 2 - 40, ≤4 - 60, ≤9 - 85, больше - 100; один автор больше 60% - ×0.7 |
| Безопасность | 20 | high/critical за год: 0 - 100, ≤2 - 75, ≤5 - 55, ≤10 - 35, больше - 15; −10 за каждую critical (до −30), −15 за незакрытые унаследованные, −25 за KEV |

Компонент без данных не считается; итог тянется к нейтральным 50 пропорционально недостающему весу:
`итог = сырой × покрытие + 50 × (1 − покрытие)`. Покрытие меньше 60% - оценка серая и с `~`. Архивированный
репозиторий - не больше 10. Оценки: A ≥ 80, B ≥ 65, C ≥ 50, D ≥ 35, F ниже. Значение сохраняется раз в
день - видна динамика за неделю.

### Поддержка веток

- **Asterisk** - политика проекта: чётные мажорные версии - LTS (4 года полной поддержки + 1 год
  исправлений безопасности), нечётные - standard (1 + 1), от даты x.0.0. Мажорная версия, у которой есть
  только rc, - «скоро».
- **Kamailio** - поддерживаются две последние ветки; более старая - «только безопасность», пока в ней
  выходят релизы, и EOL после полугода без них.
- **Остальные** - эвристика по последнему релизу ветки: до полугода «активна?», до года «редкие фиксы?»,
  дольше «вероятно EOL».

### Граф зависимостей

Связи задаются в каталоге: `deps: ['pjsip:bundled', ...]`. Тип связи определяет, как уязвимость доходит до
потребителя:

| Тип | Смысл | Как приходит исправление |
|---|---|---|
| `bundled` | копия исходников внутри (Asterisk ← pjproject) | только с релизом потребителя |
| `linked` | библиотека | пересборка или релиз потребителя |
| `optional` | необязательный модуль | так же, если модуль используется |
| `platform` | продукт поверх другого (FreePBX ← Asterisk) | обновлением платформы |
| `runtime` | отдельный сервис рядом (Kamailio + rtpengine) | обновлением сервиса отдельно |

Статус унаследованной уязвимости - эвристика по release notes потребителя после публикации CVE: `✗` ждёт
релиза (релизов не было), `?` релиз был, но без упоминания CVE или зависимости, `✓` вероятно исправлено
(упомянуто), `↻` обновить отдельно. Через `platform` и `runtime` статус берётся у промежуточного продукта;
слабые связи (`runtime`, `optional`) дальше первого уровня не протекают. Радиус поражения - сколько
продуктов унаследуют уязвимость по сильным связям (`bundled`, `linked`, `platform`).

### Метки release notes и риск обновления

`SEC` - исправления безопасности, `BRK` - breaking changes и UpgradeNote, `DEP` - устаревание, `FEAT` -
новые функции, `FIX` - исправления. Риск обновления: высокий (есть BRK), средний (FEAT или DEP), низкий
(только исправления), `?` - по заметкам не понять.

### Уязвимости

Источники - NVD (поиск по ключевому слову продукта с фильтрами против ложных срабатываний) и GitHub
Security Advisories репозитория; записи с одним CVE объединяются, предпочтение у GitHub (в нём указаны
исправленные версии). Затрагивает ли уязвимость версию - по диапазонам версий: GitHub advisories и CPE в
NVD. Если диапазонов нет, уязвимость не считается ни затрагивающей, ни безопасной - она попадает в «без
данных». [KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog) - подтверждённая эксплуатация
в атаках, [EPSS](https://www.first.org/epss/) - вероятность эксплуатации в ближайшие 30 дней.

FreePBX состоит из модулей (framework, core, endpoint, api, backup, cdr и других), и у каждого своя версия;
версия FreePBX - это версия framework. NVD часто подписывает уязвимость модуля CPE самого FreePBX с версиями
модуля: CVE-2025-57819 исправлена в endpoint 16.0.89, а не в FreePBX 16.0.89. Поэтому advisories FreePBX
берутся из [FreePBX/security-reporting](https://github.com/FreePBX/security-reporting), где у каждой записи
указан пакет - он и есть модуль. Для CVE, которых там нет, модуль ищется в CPE и описании NVD («the
endpoint module», «patched in endpoint versions»). Уязвимость модуля не сравнивается с вашей версией
FreePBX: в карточке указан модуль, в `:mine` - «модуль endpoint: проверьте его версию» (Admin → Module
Admin).

### Docker-образы

Версия продукта в образе - по самому новому тегу, похожему на версию продукта (или по описанию образа).
`ok` - актуален в своей ветке, `-N` - отстаёт на N релизов ветки, `old` - ветка больше не выпускается.
Плавающий тег `4.0` считается актуальным для ветки 4.0.

## Каталог

Каталог встроен в программу: `internal/catalog/data/`.

| Файл | Что в нём |
|---|---|
| `catalog.yaml` | 66 продуктов: `repo`, `category`, `desc`, `homepage`, `tag_filter` (какие теги - релизы), `nvd` / `nvd_filter` / `nvd_exclude` (поиск CVE и фильтры против ложных срабатываний), `deps`, `track: commits` (для проектов без релизов), `news_match`, `npm` / `pypi` / `docker` |

Описания (`desc`, `where`) - на языках интерфейса: `desc: {en: ..., ru: ...}`; программа показывает
текущий язык, если его нет - английский.

## Темы и языки

`:theme` - выбор темы с живым предпросмотром; свои темы - в разделе `themes` конфига
(`noc: {base: nord, accent: "#ffaf00"}`). `:lang en|ru` переключает интерфейс, дайджест и описания
каталога; по умолчанию язык берётся из `LANG`.

## Разработка

```sh
make test       # тесты без сети: UI-тесты на заглушках всех источников
make vet        # go vet и gofmt
make live       # снимки экранов на живых данных (нужна сеть)
make snapshot   # архивы релиза в dist/ (goreleaser)
```

| Пакет | Что внутри |
|---|---|
| `cmd/voip-info` | запуск, флаги, команды без интерфейса |
| `internal/hub` | данные и аналитика без интерфейса: загрузка источников, уязвимости, здоровье, мои версии, стек |
| `internal/ui` | виды, карточка продукта, команды, русский каталог переводов |
| `internal/digest`, `internal/export` | дайджест в Markdown, его отрисовка и сохранение |
| `internal/sources`, `news`, `ietf`, `market`, `adoption`, `dockerhub` | клиенты источников |
| `internal/relnotes`, `deps`, `eol`, `health`, `radar`, `upgrade`, `inventory`, `watch` | аналитика |
| `internal/config`, `internal/secret`, `internal/store`, `internal/fetch` | конфиг, секреты, база, HTTP с кэшем |

Интерфейс построен на каркасе [voip-tui](https://github.com/napadailo/voip-tui). Каждая видимая строка
интерфейса - на английском в коде и с переводом в `internal/ui/locale_ru.go`; тест каталога падает, если
перевода нет или он не используется.

Релиз: тег `vX.Y.Z` запускает workflow `release`, goreleaser собирает архивы для Linux и macOS (amd64, arm64)
и прикладывает их к релизу на GitHub.
